# Appleの「notarytool」を使用したアプリケーションの公証

Brianna Rentfrow（4D Inc. テクニカルサービスエンジニア）

## 概要

サイバーセキュリティは、今日ユーザーと企業の双方にとって大きな関心事です。Apple App Store以外で配布されるアプリを安全に使用できるようにするためにAppleが用意している仕組みが、「公証（notarization）」と呼ばれるプロセスです。公証を利用すると、開発者はアプリケーションをAppleに送信し、安全性を手早く確認してもらうことができます。Appleは新たに「notarytool」というツールをリリースしました。このツールによってプロセスが効率化され、アプリケーションの公証はこれまで以上に簡単になりました。

## はじめに

Appleの「notarytool」は、開発者がアプリケーションの安全性をAppleに素早く承認してもらうためのツールです。このテクニカルノートでは、このツールを使用して公証のプロセスを効率化する方法を説明します。具体的には、初回のセットアップ、コマンド1つでアプリケーションを公証する新しい方法、そして公証後のアプリケーションへのステープル（stapling）について説明します。

macOSマシンでビルドした4Dアプリケーションを別のmacOSマシンでダウンロードして開く場合や、インターネット経由で配布する場合には、公証が必要です。

## 動作要件

- macOS 11.3以降
- 4D v18以降
- Xcode 13以降
- Apple Developerアカウント
    - Developer ID Application証明書
    - App用パスワード

## 公証に向けたアプリの準備

アプリケーションを公証する前に、コンパイルとビルドを済ませておく必要があります。

まず、プロジェクトがコンパイルできることを確認します。メニューバーの「デザイン」から「コンパイラー...」を選択するとコンパイルできます。表示されたウィンドウで「コンパイル」ボタンをクリックし、処理が成功すればビルドの準備は完了です。

アプリケーションをビルドするには、もう一度「デザイン」メニューを開き、「アプリケーションビルド」を選択します。

- ビルドするファイルの種類に応じたチェックボックスを選択します。たとえば「アプリケーション」＞「スタンドアロンアプリケーションをビルド」です。このページで必要な項目をすべて入力します。アプリケーションの場合は、4D Volume Desktopの場所を指定する必要があります。

![](fig-01)

- Apple Developerアカウントにアクセスし、証明書を新規作成するか、既存の証明書をダウンロードします。ダウンロードした証明書をダブルクリックして、マシンのキーチェーンに追加します。証明書のフルネームを正確にコピーしておきます。
- アプリケーションビルドのウィンドウに戻り、「ライセンス＆証明書」タブを開きます。「アプリケーションに署名」チェックボックスを有効にし、下部の入力欄に証明書の名前をペーストします。
- これでアプリケーションをビルドできます。

これで、アプリケーションファイルが作成されているはずです。ただし、この時点でユーザーが.appファイルをダウンロードしても、アプリは開かず、代わりに「“appname.app”を開くことができません。Appleではこのソフトウェアが悪質なものかどうかを確認できません。」というメッセージが表示されます。

![](fig-02)

macOS 15 Sequoiaでは、メッセージが少し異なり、「“appname”は開いていません。Appleは、“appname”にMacに損害を与えたり、プライバシーを侵害する可能性のあるマルウェアが含まれていないことを検証できませんでした。」と表示されます。ウィンドウを閉じる「完了」と「ゴミ箱に入れる」の2つの選択肢が表示されます。

![](fig-03)

## 初回のセットアップ

公証のプロセスをできるだけ素早く行えるように、事前のセットアップが必要です。このセクションでは、アプリケーションを公証するたびに呼び出せるプロファイルを、システムのキーチェーンに設定する方法を説明します。

次に、Apple Developerのプロファイルをシステムのキーチェーンに設定します。このコマンドの実行は最初の1回だけで済みます。以降はアプリを公証するたびにApp用パスワードやログイン情報を入力する必要はなく、notarytoolにこのキーチェーンプロファイルを指定するだけで済みます。

- コマンドラインで次のコマンドを入力します。

```sh
xcrun notarytool store-credentials --apple-id "EMAIL" --team-id "TEAMID"
```

**注：**「EMAIL」はApple Developerのメールアドレスに、「TEAMID」は**Apple Developerアカウント**で確認できるチームIDに置き換えます。

- Enterキーを押すと、プロファイルの名前を入力できます。この名前は、以降毎回参照するものです。この例では「notaryTN」という名前を使用します。
- 次にApp用パスワードを求められるので、**Appleアカウント**で取得したパスワードをペーストします。
- App用パスワードは、次の手順で取得します。
    - <https://account.apple.com/>にアクセスしてサインインします。
    - 表示されたページで「App用パスワード」と書かれた項目をクリックします。
    - ここでApp用パスワードを取り消したり、新規に追加したりできます。

**注：**App用パスワードはWebサイト上で表示できません。取り消しと追加のみが可能です。

これでプロファイルを使用する準備ができました。以降は次のオプションでプロファイルを指定できます。

```sh
--keychain-profile "notaryTN"
```

## 公証の前にアプリケーションにファイルを追加する

**注：**このセクションは、すべてのアプリケーションに該当するわけではありません。4Dが自動的に署名する場所に置くことのできない追加ファイルを、アプリケーションが必要とする場合にのみ該当します。

アプリケーションによっては、通常の構成に含まれないために最初のビルドには含まれないファイルやフォルダーを追加する必要があります。その場合は、公証の手順に進む前に、次の手順を実行します。追加ファイルを必要としないアプリケーションでは、この手順は不要です。

まず、通常どおりアプリケーションをコンパイルしてビルドします。

次に、プロジェクト内の必要な場所にファイルを追加します。

続いて、新しい4Dプロジェクトを作成します。このプロジェクトのResourcesフォルダー内に、次の内容のシェルスクリプトファイル（.sh）を新規作成します。

```sh
IFS=$'\n'; set -f
for f in $(find "${product_path}" -type f \( -perm +111 -o -name "*.dylib" -o -name "*.js" -o -name "*.json" -o -name "*.html" -o -name "*.so" \) | sort -r )
do xattr -c "${f}";
codesign --verbose --options=runtime --timestamp --force --sign "${sign}" --keychain ${keychain} --entitlements "${entitlements_path}" "${f}";
done
for f in $(find "${product_path}" -type d \( -name "*.app" -o -name "*.framework" -o -name "*.bundle" -o -name "*.plugin" -o -name "*.kext" \) | sort -r )
do xattr -c "${f}";
codesign --verbose --options=runtime --timestamp --force --sign "${sign}" --keychain ${keychain} --entitlements "${entitlements_path}" "${f}";
done
unset IFS; set +f
```

エンタイトルメント（entitlements）ファイルをすでに用意している場合は、新しいプロジェクトのResourcesフォルダーに入れます。用意していない場合は、4Dのエンタイトルメントファイルを使用できます。

4D.appを右クリックして「パッケージの内容を表示」を選択します。Resourcesフォルダーを開き、4D.entitlementsを探します。このファイルを新しいプロジェクトのResourcesフォルダーにコピーします。

新しく作成したプロジェクトに、次の内容の4Dメソッドを作成します。変数$signには、コンピューターのキーチェーンにある証明書の名前を入力してください。エンタイトルメントファイルの名前が、Resourcesフォルダー内のファイル名と一致していることを確認してください。このコードは、アプリが開発者のデスクトップにあることを前提としています。また、スクリプトファイルの名前も一致させてください。この例では、スクリプトの名前を「script.sh」としています。

```4d
//name of your certificate
$sign:="CERTNAME (CERTNUMBERS)"
//your keychain profile
$keychain:="notaryTN"
//Location of the .app file (this example is an app called appname.app that is on the desktop)
$product_path:=Folder(fk desktop folder).folder("appname.app").path
//entitlements file. I use the one from 4d
$entitlements_path:=File(File("/RESOURCES/4D.entitlements").platformPath; fk platform path).path

SET ENVIRONMENT VARIABLE("sign"; $sign)
SET ENVIRONMENT VARIABLE("keychain"; $keychain)
SET ENVIRONMENT VARIABLE("product_path"; $product_path)
SET ENVIRONMENT VARIABLE("entitlements_path"; $entitlements_path)

$script:=File(File("/RESOURCES/script.sh").platformPath; fk platform path).path

var $in; $out; $err : Text
LAUNCH EXTERNAL PROCESS("bash "+$script; $in; $out; $err)

ALERT("Done")
```

このメソッドを実行して「Done」というアラートが表示されれば、アプリケーションへの署名は完了し、公証とステープルの準備が整います。

## 公証

### アプリケーションとコンポーネントの公証

プロファイルの設定が済んでいれば、アプリケーションの公証が必要になるたびに次の手順で簡単に公証できます。まず、アプリケーションをzipで圧縮します。アプリケーションを公証するには、ターミナルで次のコマンドを実行します。

```sh
xcrun notarytool submit "[ZIP FILE PATH]" --keychain-profile "notaryTN" --wait
```

**注：**「[ZIP FILE PATH]」は、署名済みのアプリケーションを含むzipファイルのパスに置き換えます。角括弧は含めません。ファイルをターミナルのウィンドウにドラッグすると、正しいパスを入力できます。

このコマンドを入力すると、アップロードの進捗がパーセントで表示されます。

続いて「In progress…」というステータスが表示され、処理が続いている間はドットが追加されていきます。この表示は、公証のプロセスが完了し、承認されたかどうかのステータスが表示されるまで続きます。

### コンパイル済みデータベースの公証

コンパイル済みデータベースに正しく署名するには、追加の手順が1つ必要です。アプリケーションのビルド時に、4Dは「lib4d-arm64.dylib」ファイルに正しく署名しません。これを回避するには、このライブラリに手動で署名する必要があります。このライブラリは、コンパイル済みデータベースの「Libraries」フォルダーにあります。ターミナルで次のコマンドを実行します。

```sh
codesign -s [IDENTITY] -o library [Path to lib4d-arm64.dylib]
```

開発者アカウントと証明書に紐づいたコード署名ID（codesign identity）が必要です。マシン上のコード署名IDを確認するには、ターミナルで次のコマンドを実行します。

```sh
security find-identity -v -p codesigning
```

IDとは、IDの名前の前に表示される英数字の文字列のことです。

これで、コンパイル済みデータベースもアプリケーションやコンポーネントと同じように署名できるようになります。フォルダー全体を再度zipで圧縮し、公証に送信してください。

### 公証のログファイル

公証が承認されたかどうかは、ログで確認することをお勧めします。送信時に表示されるIDを指定して、次のコマンドを実行します。

```sh
xcrun notarytool log "[ID_RECEIVED]" --keychain-profile "notaryTN" developer_log.json
```

アプリケーションが承認されなかった場合は、その理由がログに記録されています。ログには、注意すべき警告が含まれている場合もあります。

**注：**ログの名前は自由に付けることができます。この例では「developer_log.json」としています。これはパスなので、.jsonファイルはアクセスしやすい任意の場所に保存できます。

## アプリケーションへのステープル

アプリケーションの準備の最後のステップは、ステープルです。アプリケーションが公証されると、公証済みであることを示すチケットが生成され、Appleのサーバーに保存されます。開発者はこのチケットをアプリケーションに直接ステープル（添付）できます。これにより、Gatekeeperがオンラインでチケットを検索する必要がなくなり、インターネット接続の有無にかかわらずチケットを確認できるようになります。

**注：**アプリケーションの種類によっては、ステープルできないものがあります。たとえば、「.4dbase」形式の4Dコンポーネントはステープルできません。ステープルできるファイル形式は「.app」「.dmg」「.pkg」のみです。

- アプリケーションが公証されたら、zipファイルを展開します。
- .appファイルに対して次のコマンドを実行します。

```sh
xcrun stapler staple [PATH]
```

- 成功すると「The staple and validate action worked!」というメッセージが表示されます。これで、アプリをダウンロードして初めて起動するときに、インターネットに接続する必要がなくなります。

## まとめ

このテクニカルノートでは、アプリケーションに署名し、公証し、ステープルする方法を説明しました。Appleはセキュリティ対策として、すべてのアプリケーションが安全であることをシステムで確認することを求めています。ここで説明した内容により、macOSマシンで実行するアプリケーションを配布できるようになります。
